# kkt v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용자 전용 맥 카카오톡 CLI `kkt` 를 독립 저장소로 새로 만들어, watcher 가 쓰던 포크본 kkt 를 대체하고 읽기·사진·공지·doctor 까지 제공한다.

**Architecture:** Swift 패키지 하나(라이브러리 `KktCore` + 실행 파일 `kkt`). DB 는 SQLCipher 로 읽기 전용, UI 는 AX + pid 키 이벤트로 백그라운드 조작. 포크(`~/.local/src/kakaocli`, 브랜치 `local/kakaotalk-26.9`, HEAD 769c9ca)의 우리 코드는 옮기고, kakaocli(MIT)는 필요한 부분만 이식해 고지한다.

**Tech Stack:** Swift 6 (swift-tools-version 6.0, macOS 14+), swift-argument-parser ≥1.5.0, brew `sqlcipher`(pkg-config), XCTest, Vision(OCR). watcher 쪽은 Node 24 + `node --test`.

**Spec:** `docs/dev/specs/2026-11-03-kkt-cli-design.md` (승인 2026-11-03)

## Global Constraints

- 저장소 `<repo>`, GitHub `<owner>/kkt` **private**. 로컬 git 설정: `gh.account=<owner>`, `user.name=<owner>`, `user.email=<email>`.
- 카카오 서버 로그인·서버 API 금지. 비밀(DB 키)은 파일·로그·출력에 남기지 않는다(매 실행 계산).
- 숫자·문자열 리터럴은 `KktConstants`(및 하위 enum)에. TODO/FIXME/HACK 금지, `print` 는 출력 모듈(`KktOutput`)에서만. 영어 코드·주석. 파일 400줄 이하.
- AX·DB·시계·프로세스 실행·sleep 은 주입해 단위테스트한다.
- 기계용 명령 출력(serve NDJSON, send/join/contact 한 줄 JSON)은 포크본과 **바이트 단위로 같은 키·값 모양**(스펙 5절). 기계용 명령에 추가되는 reason 코드는 `chat_window_open`, `kakaotalk_in_use`(카톡이 맨 앞 앱 — 사용자가 쓰는 중이라 키 입력이 입력기에 섞임, 2026-11-03 실측), `kakaotalk_not_running` 셋(watcher 는 앞의 둘을 대기, 마지막을 일반 실패로 다룬다). 나와의 채팅은 채팅 목록에 보일 때만 연다(이름 검색은 멤버 이름까지 걸려 477행, 실측).
- 메인 창이 아닌 카톡 창이 하나라도 있으면 UI 조작을 시작하지 않고 `{"result":"failed","reason":"chat_window_open"}`(스펙 11절 3). kkt 가 연 창은 같은 실행에서 닫는다.
- 채팅 목록 행은 `AXVisibleRows` 로만 읽는다(없을 때만 AXChildren).
- 잠금 경로 기본값 `~/.config/kkt/kkt.lock`, 설정 `lockPath` 로 바꿀 수 있다. 전환 전 설치본(`~/.local/bin/kkt-next`)은 `~/.review-automation/kakao/kkt.lock` 을 쓴다.
- 전송 간격 최소 2.0초: 마지막 전송 시각 파일(`<lockPath>.last-send`)을 보고 잠금을 잡은 채 기다린다.
- 설정 `~/.config/kkt/config.json`(0600): `{"userId": Int?, "lockPath": String?, "verifiedKakaoVersions": [String]}`. 환경변수 `KKT_USER_ID` 가 설정보다 우선.
- 구현은 Codex(`codex exec -s workspace-write -m gpt-6.1-sol -c model_reasoning_effort=high … < /dev/null`), Codex 가 `.git` 에 못 쓰면 번들로 받는다. 실측·검증은 Fable. Codex 는 질문 말고 구현.
- 커밋 Conventional Commits. 푸시는 Task 11 에서 <owner> 확인 후.

## Review Focus

1. **카톡이 실행 중이 아니거나 로그아웃 상태** — UI 명령은 즉시 `automation_failed`가 아니라 doctor 와 같은 원인 코드(`kakaotalk_not_running`)로 실패해야 하고, serve 는 DB 만 있으면 계속 돈다. → Task 4 테스트 `ui command fails fast when KakaoTalk is not running`.
2. **같은 이름 방 두 개** — send 는 추측하지 않고 `ambiguous_name`. 이름은 DB 표시 이름 기준. → Task 5 테스트 `send refuses ambiguous room names`(포크 테스트 이식 확인).
3. **사용자 검색어가 한글 조합 중이거나 비어 있음** — 복원은 원래 값과 정확히 같아야 하고, 비어 있었으면 비운 채로. → Task 4 테스트 `search restore keeps empty and Korean text`.
4. **DB 가 잠깐 잠김(카톡이 쓰는 중)** — serve 는 연속 30회 오류 전까지 계속, 읽기 명령은 3회 재시도 후 `database_unavailable`. → Task 3 테스트 `serve survives transient busy errors`, Task 7 테스트 `read command retries busy database`.
5. **16자리 넘는 id** — 모든 JSON 출력에서 숫자 그대로, 입력 `--chat-id` 도 Int64 로 정확히. → Task 3 테스트 `large ids are emitted exactly`, Task 7 테스트 `messages accepts int64 chat id`.
